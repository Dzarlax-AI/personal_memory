# Retrieval evaluation

`cmd/eval-memory` evaluates fact recall and flat or hierarchical document
retrieval against a versioned golden dataset. It produces deterministic JSON
and Markdown reports and can compare a candidate report with a saved baseline.

## Data boundary

The checked-in dataset under `evaldata/public/` is synthetic. It contains no
production facts, document paths, point IDs, or credentials. Version 1 uses
small, explicitly synthetic vectors so CI can exercise Qdrant ranking without
running TEI. A future dataset may contain vectors generated by a pinned TEI
revision; its complete model identity must be recorded in the fixture.

Private datasets belong under `evaldata/private/`. Local reports belong under
`eval-results/`. Both paths are ignored by Git. Do not copy production payload
text into public fixtures or CI artifacts.

## Fixture mode

Fixture mode validates the complete dataset before contacting Qdrant. It then
creates three unique collections whose names begin with `eval_`, seeds the
synthetic points, evaluates every query, and deletes only collections created
by the current run. Existing `memory`, `doc_chunks`, and `doc_folders`
collections are never opened for mutation.

```bash
make eval-public
```

Equivalent direct invocation:

```bash
go run ./cmd/eval-memory run \
  --source fixture \
  --dataset evaldata/public/v1/dataset.json \
  --qdrant-url http://127.0.0.1:6333 \
  --json eval-results/public.json \
  --markdown eval-results/public.md
```

A hard kill can leave a uniquely named `eval_*` collection behind. Inspect the
Qdrant collection list before deleting anything; never use a broad wildcard
against a shared instance.

## Live mode

Live mode is read-only. It searches the logical collection names declared in
the dataset and does not create collections, upsert points, delete data, or
increment recall counters.

Queries may contain precomputed vectors:

```bash
go run ./cmd/eval-memory run \
  --source live \
  --dataset evaldata/private/my-live-set.json \
  --qdrant-url http://127.0.0.1:6333 \
  --json eval-results/live.json \
  --markdown eval-results/live.md
```

When a private query omits its vector, add `--embed-url`. The CLI reads TEI
`/info` first and rejects model ID, revision, dtype, or pooling mismatches
before embedding the query.

## Baseline comparison and gates

```bash
go run ./cmd/eval-memory compare \
  --baseline evaldata/public/v1/baseline.json \
  --candidate eval-results/public.json \
  --enforce-gates
```

Comparison reports aggregate and per-query metric deltas. Retrieval degradation
is diagnostic by default. A non-zero gate exit occurs only when
`--enforce-gates` is used and the candidate violates thresholds explicitly
declared in the dataset, or when input/execution fails.

The evaluator reports:

- Hit@K;
- mean reciprocal rank;
- nDCG@K with relevance grades from 1 through 3;
- forbidden lifecycle result IDs;
- result IDs whose payload is missing `text`.

## Updating a public dataset

Treat the dataset and baseline as one reviewed unit:

1. Bump `dataset_version` for semantic corpus or relevance changes.
2. Record the complete embedding identity; never label constructed vectors as
   TEI output.
3. Run fixture mode twice into separate output files.
4. Compare both JSON files and both Markdown files byte for byte.
5. Review every expected ID, grade, forbidden ID, and gate change.
6. Replace the checked-in baseline with a freshly generated Qdrant report.
7. Run `make test` and `make eval-public`.

The canonical report deliberately excludes timestamps, physical temporary
collection names, and latency. Those values would make regression artifacts
non-reproducible.
