Scope and acceptance

Persist safe terminal write-shadow failure codes in private operator journals and make write.shadow_timeout_ms configurable, default 1000 ms and range 1–30000 ms (zero means default). Preserve client opt-in, independent feature switches, no provider retries, advisory grouping and deterministic storage. Validate with isolated tests and one genuine new fact through the deployed MCP server.

Evidence and contract

The worker currently discards unavailable/invalid outcomes and caps all jobs at one second. A real-fact diagnostic reproduced a one-second read timeout; the same request later yielded personal-memory. Add optional reason_code and duration_ms to existing private write journals. Reasons are fixed enums, never raw errors, provider bodies, fact content, endpoints or credentials. Record timeout, cancellation, HTTP/auth/rate-limit, transport, invalid response, request, catalog/egress/budget rejection and queue saturation. Journal persistence errors emit a fixed content-free warning. Historical journals remain readable.

The shadow context uses the new budget. A dedicated write adapter uses that timeout as its fallback; an explicitly shorter profile timeout still wins. Synchronous writes and read inference keep their one-second operation context. Production candidate uses shadow_timeout_ms=10000 and the write profile timeout_ms=10000, with six daily calls and unchanged approved catalog. Older binaries reject the new field, so rollback restores the previous image and configuration together.
