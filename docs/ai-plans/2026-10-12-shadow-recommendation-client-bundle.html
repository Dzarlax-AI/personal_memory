Desired behavior and limits

  1. Discover the exact tool before use. If absent, retain baseline memory behavior and report that recommendation lookup is unavailable.
  2. Never grant allow_ai_processing automatically because the tool exists. Preserve per-request permission and operator admission; this workflow adds no egress authorization.
  3. After an eligible successful write returns ai.operation_ref, read it once. If pending, permit one delayed follow-up at the existing client example's cadence; do not busy poll or retry inference. Still pending means preserve the reference for a later user-requested check.
  4. Present primary suggestion separately from related recommendations. All results remain advisory; do not automatically update tags, namespaces, lifecycle or facts. Preserve explicit client tags.
  5. Handle decided, abstained, failed, outdated, not_found and unavailable distinctly. Never invent a project or collapse multiple_projects, other_project, non_project and insufficient_context.
  6. No lookup for duplicate/bypassed writes or missing reference; no retroactive scan of historical facts. Tasks remain Todoist operations.
