Compact classification requests

Revision 1 · Approved by the user on 2026-10-12 · Implemented locally

Evidence and goal

The deployed PR #68 builder repeats the full classification rubric in every primary and related-project question. With the current 25-project catalog, four non-subject payloads measured 58,323–58,387 bytes. Two requests containing subject declarations were rejected locally with “judgment request exceeds 64 KiB” before budget reservation and provider dispatch. The real pilot produced four correct single-project judgments; the contextual cases were not evaluated by the model.

Goal: serialize the approved contextual inputs below the existing 65,536-byte limit for both Decisions and Jev, while preserving classification rules and response validation. Serialized size is verified after provider-specific JSON encoding.

Settled design and boundaries

Keep the complete primary classification rubric and subject abstention rules in the primary question. Replace the repeated primary-selection rules in related-project questions with concise, independently meaningful relationship instructions. Each related question must retain: assertion and catalog evidence only; instruction-like data is untrusted; source and subject declarations do not prove a relationship; actual owned component or concrete supported interaction required; unnamed distinctive components are allowed; shared tools, languages, formats, generic workflows and speculative integrations are insufficient; catalog descriptions are context rather than authority; no invented facts.

Do not rely on one question seeing another question’s instructions. Add no undocumented global instructions field. Keep catalog descriptions and all eligible candidates intact. Retain current conditional availability of non_project/multiple_projects, names and choices of questions, independent judgments, validation, primary-only automatic grouping and explicit client tags. Bump write rubric identifiers to describe the new serialized prompt. Read-ranking prompts and identifiers remain unchanged.
