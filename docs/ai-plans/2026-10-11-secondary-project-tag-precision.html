Desired contract and proposed scope

Primary ownership and secondary project participation require different decisions. A secondary project is eligible only when the assertion actually concerns its component, or describes a concrete interaction involving that project supported by its catalog description. Names need not appear if the component is distinctive. Shared languages, file formats, tools, generic operations, or merely possible integrations are insufficient. Missing support means no secondary tag.

Proposed immediate policy: use only the selected primary project for AI-generated grouping; preserve every explicit client tag. Keep related-project outputs as advisory evaluation evidence until secondary precision is validated. A correct primary prediction must not make an incorrect full tag set count as success. Preserve ordinary/non-project handling, abstention, namespace, ownership and egress rules.

Also tighten secondary-question wording for both Decisions and Jev, with fixed examples covering generic overlap and actual component interaction. Do not add a granola-save blacklist, lexical name gate, or uncalibrated probability cutoff. Do not edit catalog descriptions to teach one test answer.
